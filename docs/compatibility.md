## Codex: المهارة مباشرة

للتثبيت في مشروع مستهدف، ضع نسخة مجلد `fikra/` كاملًا داخل `.agents/skills/` في جذر ذلك المشروع، بحيث يصبح الملف `.agents/skills/fikra/SKILL.md`. هذه هي بنية المشروع الموثقة في [دليل Codex الرسمي](https://learn.chatgpt.com/docs/build-skills). افتح جلسة جديدة واطلب: «استخدم $fikra لإعداد حملة مختصرة على Instagram لمكتبة، هدفها تشجيع القراءة. نصوص فقط».

في التقييم الأصلي وُجد رابط محلي `~/.codex/skills/fikra`؛ الاختبار الحي اللاحق استخدم مسار Plugin المثبت الموضح أعلاه. لا تثبّت نسخة ثانية في البيئة نفسها إذا كانت المهارة متاحة أصلًا.

## Codex: حزمة Plugin

من جذر هذا المستودع:

```bash
python3 scripts/build_plugin.py
python3 scripts/build_plugin.py --check
```

الحزمة المستقلة هي `plugins/fikra/`، بما فيها المجلد المخفي `.codex-plugin/` والترخيص. الملفات داخل `skills/fikra/` مولّدة؛ عدّل المصدر ثم أعد البناء. يفشل `--check` عند اختلاف بايتات أو وجود ملف زائد. لا يحذف السكربت الملفات الزائدة؛ راجعها يدويًا. لا تُضمّن المستودع كاملًا أو `output/` عند توزيع الحزمة.

للتحقق بأدوات المهارات المثبتة، استخدم Python يحتوي على PyYAML، وحدّد جذري المهارتين الحقيقيين في بيئتك:

```bash
python3 "$SKILL_CREATOR_ROOT/scripts/quick_validate.py" ./fikra
python3 "$PLUGIN_CREATOR_ROOT/scripts/validate_plugin.py" ./plugins/fikra
```

المتغيران أعلاه مساران يحددهما المستخدم، وليسا إعدادين خاصين بـCodex. لا تأتي أدوات التحقق الخارجية ضمن الحزمة.

لم يُنشأ أو يُعدّل marketplace في هذه المرحلة. بحسب `codex plugin add --help` المحلي، التثبيت يتم من marketplace، وليس بأمر تثبيت مجلد Plugin مباشرة. بعد أن يُدرج مسؤول التوزيع هذه الحزمة باسم `fikra` في marketplace فعلي ويتحقق من مصدرها، تكون صيغة التثبيت:

```text
codex plugin add fikra@MARKETPLACE_NAME
```

استبدل `MARKETPLACE_NAME` بالاسم الفعلي المؤكد. إذا كان marketplace غير افتراضي ولم يُضف بعد، تؤكد مساعدة CLI الصيغة `codex plugin marketplace add SOURCE`، حيث `SOURCE` مصدر marketplace الحقيقي. هذه تعليمات توزيع عامة مشروطة، لم تُنفّذ ضمن تحديث التوثيق ولا تعني أن المستودع الحالي marketplace. نجح بصورة منفصلة اختبار النسخة المثبتة `fikra@personal v0.1.0` كما هو موثق أعلاه؛ لم يُعدّل marketplace أو النسخة المثبتة في هذا التحديث. بعد التثبيت افتح جلسة جديدة واختبر طلب النصوص السابق، ثم طلب صورة وتحقق من توقفه لاعتماد النص ثم موافقة الأداة. لا توافق على الإنتاج في اختبار التحميل.

## Claude: نتيجة الاختبار الحي

بحسب تقرير المستخدم، نُفّذ الاختبار الحي النهائي بعد رفع `fikra-claude-skill-v3.zip`، وكانت نتيجته **Pass في النطاق النصي المختبر**:

- اكتشف Claude مهارة fikra المرفوعة وقرأ ملفاتها.
- أنشأ حملة Instagram مختصرة بلغة عربية مبسطة وافق عليها المستخدم.
- تجنب الادعاء غير المدعوم بأن عشر دقائق تكوّن عادة.
- عرض نصوص الشرائح والكابشن وشرح المقصود.
- طلب اعتماد النصوص قبل اقتراح الإنتاج.
- لم يُنتج وسائط ولم يربط حسابات أو ينشر أو يجدول.

حلّت هذه النتيجة محل حالة انتظار إعادة اختبار المصداقية؛ اختبار Claude ليس معلقًا. هذا توثيق لتقرير المستخدم، وليس إعادة تشغيل ضمن هذه المهمة. راجع [تقرير الإصلاح والاختبار النهائي](release-v0.1.md). لا نعمم النتيجة على كل واجهات Claude أو كل النماذج؛ تبويب الاختبار وإصدار النموذج غير محددين.

## Replit Agent

ضع مجلد المصدر كاملًا في `.agents/skills/fikra/` داخل جذر مشروع Replit. اطلب من Agent استخدام Fikra لإعداد الحملة النصية السابقة. توثق [Replit بنية مهارات المشروع](https://docs.replit.com/features/agent/skills)؛ لا نعطي أمر Replit CLI أو إعدادًا غير موثق. أثبت الاختبار الحي المبلغ عنه اكتشاف المهارة من `.agents/skills/fikra/SKILL.md` وطلب فكرة المحتوى ونوع صاحب الحساب وهدف الحملة، ثم إنشاء حملة Instagram مختصرة بفصحى مبسطة وتجنب الادعاء غير المدعوم بأن عشر دقائق تكوّن عادة. لم يُنتج وسائط ولم ينشر أو يربط حسابات.

**النتيجة: نجاح سلوكي أساسي، مع توقف الخطوة النهائية بسبب حد Replit المجاني.** انتهت الأرصدة بعد عرض المسودة، فلم يكتمل سؤال الاعتماد النهائي. هذه الخطوة غير مكتملة التحقق، وليست Pass أو Fail مثبتة للمهارة؛ يلزم استكمالها عند إتاحة الاستخدام. لا نعمم هذه النتيجة على المسار الكامل أو التكاملات، وقد نجح اختبار Claude النهائي بصورة مستقلة.
